# Contribution art architecture

## Stack and commands

Bun runs dependency-free JavaScript. Git stores empty commits as pixels; no
package install, OAuth application, external painter, or service is required.

```sh
bun run preview
bun test
bun run status
python -m http.server 8765 --bind 127.0.0.1
# Open http://127.0.0.1:8765/art/preview.html
```

No build or production web deployment is needed; SVG and HTML are standalone.
To update an unpublished run, commit source changes, confirm a Git identity
already attributed to your account, and use these separate commands:

```sh
bun run generate
bun run verify
bun run publish
```

Generation requires a clean checkout on `codex/rudy-contribution-art` and the
exact Radishoux/business origin. It counts artwork in the current branch,
adds only deficits, and does nothing once the target is met. Generation never
pushes. Publication verifies targets, the GitHub default branch, and ancestry,
then sends fast-forward batches of at most 500 pending commits. It never
force-pushes, deletes branches, or changes the default branch itself.

## Files and module dependencies

- `index.js`: glyphs, date plan, SVG/HTML preview, Git generator and publisher.
- `index.test.js`: orientation, date boundaries, 1/50 targets, incremental generation, and preview mapping.
- `art/plan.json`, `art/rudy-code.svg`, `art/preview.html`: generated by preview.
- `.git/art-run.json`: local publication state (base, tip, branch, added, target); never uploaded.
- `.git/calendar-before.json`: optional local GraphQL snapshot; never uploaded.

Dependency direction: tests -> index.js -> Bun standard-library APIs -> Git.
The preview uses no network assets or imported modules.

## Data model and invariants

A plan has an ID, Sunday start, width, branch, background range, intensity
settings, disclosure, totals, and ordered `{date, count, glyph, x?, y?}` days.
x counts weeks; y counts days from Sunday. Date = `start + 7*x + y`.

Every day from 2025-10-08 through 2026-10-06 has a target of 1 art commit;
82 painted dates override that target to 50 total, not 51. This makes 282
background days and 4,382 art commits. All dates are unique and in the past.
GitHub may show more contributions because other work also counts.

Author and committer dates are equal at noon UTC plus a few seconds, avoiding
DST shifts. Every commit explicitly identifies decorative art and its actual
generation date. Artwork messages start with `pixel-art: rudy-code-2026`.
Existing counts include only matching messages reachable from the current HEAD.
A target lower than existing art is rejected, since it would require rewriting
history. Existing 40-commit pixels therefore receive only 10 more commits.

All commits from one generation share its starting file tree. Verification
checks exact daily counts, equal author/committer dates, range size and tree
identity. The default branch and associated author email are needed for GitHub
contribution credit. GitHub chooses color thresholds; preview shades are estimates.

## End-to-end flow

R's upper-left pixel is week 6, Sunday: 2026-02-15. The plan targets 50 commits.
If the previous design has 40, `missingPlan` requests 10. Preview renders a
strong green cell with a date/count tooltip. Generation feeds Git fast-import
a linear chain of 10 empty commits, saves local run metadata, and verifies the
whole plan. Publication compares the remote tip and pushes only missing history.
GitHub indexes those commits under the associated account.

## Decisions and recovery (2026-10-07)

Original master: `99a624f93f0584dbb7f5c5ddefaed0c0b47f2fc0`. Its 30,500 generated
gitfiti commits followed `2e511fea512ae2b5d5e94b24e0721918c53b7dc6`. The initial
live calendar showed only the final 1,000 artwork commits. This is an observation,
not a documented indexing limit. Smaller pushes allow incremental verification.
A huge single push was rejected because the earlier result was incomplete;
force-replacing master was rejected because all old history can be retained.

The replacement branch starts at `2e511fea512ae2b5d5e94b24e0721918c53b7dc6`,
preserving earlier history. Its first design used 3,280 commits on 82 days.
The requested background and 50-commit pixels add 1,102 commits. Rebuilding the
published design from scratch was rejected to avoid duplicates or a force push.

Master stays untouched. Restore the former default with:

```sh
gh repo edit Radishoux/business --default-branch master
```

GitHub documents up to 24 hours for contribution changes. Do not regenerate
art to trigger indexing. Compare actual dates after switching; old-art removal
and new-art indexing can be delayed independently.

## Gotchas

- January 4 is Sunday; transposing axes destroys the design.
- Source changes must be committed before generation; the artwork commits do
  not contain uncommitted working-tree files.
- Targets are fixed dates, not a daily scheduler. They never generate future days.
- The old design remains on master but is excluded from the default branch.
- The optional preview baseline subtracts the 1,000 old pixels observed as indexed;
  it does not guarantee GitHub's final colors.
- The rolling year crops lettering after January 2027; select 2026 to retain it.
- Keep `.git/art-run.json` until publication completes. If lost, recover its base
  from the tooling commit, its tip from the final artwork commit, and its `added`
  count from `git rev-list --count BASE..TIP`. Never guess or skip verification.
- Publication checks that its remote tip is an ancestor, so concurrent divergent
  work stops the push instead of being overwritten.
